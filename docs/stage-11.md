## Что сделано

  - `/expert/applications/:id` — экран оценки: заголовок «Заявка № …» со статусом и плашкой
    «Ответить за N мин / Норматив — 15 минут»; **галерея** с увеличением 100–400 %
    (прокрутка увеличенного снимка внутри рамки, листание стрелками клавиатуры, «1 из 4»),
    миниатюры с замечаниями анализа фото («Слишком тёмное»); карточки «Со слов клиента» и

    «Отправить предложение», «Запросить фото» (комментарий обязателен) и «Отклонить заявку»

## Как проверить
```bash
cd backend && alembic upgrade head && python -m app.seed && uvicorn app.main:app --reload
cd frontend && npm run dev          # http://localhost:5173 → «Войти» → карточки ролей
cd frontend && npm test && npm run lint && npm run format:check && npm run design:check && npm run build
```
Сценарий в браузере (всё без Swagger): клиент создаёт и отправляет заявку → `expert@lombard.kz`:
«Очередь» → заявка → «Взять в работу» → «Отправить предложение» → клиент принимает и вызывает
курьера → `courier@lombard.kz`: «Выехал к клиенту» → «Изделие у меня» → «Доставил в ломбард» →
эксперт: «Осмотр» → «Подтвердить осмотр» → клиент получает деньги → `admin@lombard.kz`:
дашборд, «+30 дней» для просрочки. Пароль всех демо-аккаунтов — `demo1234`.

## Принятые решения
- **Навигация админа — в шапке**, как у других ролей, а не боковой панелью из макета:
  один `AppLayout` на все кабинеты, на телефоне шапка уже прокручивается горизонтально.
  Пункты «Заявки» и «Займы» из макета не добавлены — отдельных админских экранов для них нет,
  данные видны на дашборде.
- **Норматив ответа эксперта — 15 минут** (константа `REVIEW_SLA_MIN`, как в макете); в
  backend его нет, отсчёт идёт от последнего перехода в «Предоценка готова».
- **Диаграмма «Выдано по дням» считается на клиенте** из списка займов (`GET /api/loans`
  админу отдаёт все): в `/admin/stats` нет разбивки по дням. Для учебного объёма данных это
  дёшево; при росте — отдельный эндпоинт. Единица оси (тыс. или млн ₸) выбирается по
  масштабу и вынесена в заголовок, как в макете.
- **Автоназначение** — на клиенте: каждому выезду без курьера — наименее загруженный курьер его
  города (то же правило, что у backend при вызове курьера); при равной загрузке — первый по
  списку.
- Переключатель периода — «Неделя / Месяц» (без «Сегодня»): за один день столбчатая диаграмма
  бессмысленна.
- Кнопки «Клиент не отвечает» и нижнего таб-бара из артборда 07 нет: в backend нет такого
  статуса, а разделы курьера помещаются в шапку. Схема-карта маршрута заменена ссылкой
  «Маршрут в 2ГИС».
- Вариант «Нужно фото» в переключателе пробы заменён на «Не видно» (`hallmark_confirmed = null`):
  запрос фото — отдельная кнопка с комментарием клиенту.
- Скрытые для глаз подписи (`visually-hidden`) внутри прокручиваемых таблиц давали
  горизонтальную прокрутку страницы — у `.tableWrap` и диаграммы теперь `position: relative`,
  а скрытая таблица диаграммы обёрнута в `div`.

## Известные проблемы и техдолг
- Общие стили кабинетов (`page`, `back`, `meter`, таблицы) частично дублируются между
  `Client.module.css`, `Expert.module.css` и `Admin.module.css` — стоит вынести в
  `components/` при финальной полировке.
- Очереди и выезды обновляются опросом (30–60 с), без WebSocket.
- У админа нет экрана заявки и действий `issue_funds` / вызова курьера за клиента (API есть).
- В «Пользователях» нельзя сменить город сотрудника и сбросить пароль (API смены города
  есть, сброса пароля — нет).
- Миниатюры с длинным замечанием обрезаются («Низкий к…»), полный текст — под большим фото.
- Перемотка времени — глобальная для всего сервера (так устроен backend).
