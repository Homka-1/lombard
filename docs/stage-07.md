## Принятые решения
- **Слоты** фиксированные по 2 ч в рабочее время по Казахстану; клиент передаёт `slot_start`
  из списка — произвольное время не принимается. Вместимость слота = число активных курьеров
  города, курьер занят, если у него есть неотменённая задача, пересекающаяся со слотом
  (выполненная тоже занимает своё время).
- **Город обслуживания** = город активного курьера (`User.city`); отдельного справочника нет.
- **Автоназначение** сразу при вызове: свободный в слоте курьер города с минимумом
  незавершённых задач, при равенстве — меньший id. Админ может переназначить, пока курьер
  не выехал. Задача без курьера в текущем потоке не возникает (поддержана в фильтрах на
  будущее).
- **Шаги курьера** делает только назначенный курьер (админ — 403, чужой курьер — 404, как
  «нет такой задачи»); порядок шагов проверяется доменной таблицей (409).
- Курьер не читает карточку заявки (`/api/applications/{id}` — 403): всё нужное (номер,
  изделие, клиент, адрес, телефон) — в задаче.
- **Осмотр** может провести любой эксперт (не обязательно оценивавший). Сумма может только
  уменьшиться: клиент соглашался на максимум из оферты. Сама оферта не меняется — история.
- Контактный телефон по умолчанию — из профиля клиента; хранится в E.164, отдаётся и в
  отформатированном виде (`contact_phone_display`).

## Известные проблемы и техдолг
- Нет отмены вызова курьера и нет пути «изделие не прошло осмотр» (подделка/несоответствие):
  в машине состояний нет перехода из `COURIER_SCHEDULED`/`ITEM_DELIVERED` назад или к
  возврату. Сейчас эксперт может только уменьшить сумму. Если нужно — добавить переходы и
  задачу `RETURN` без займа.
- После уменьшения суммы на осмотре клиент не может отказаться (нет перехода) — решение
  о согласии на новую сумму не моделируется.
- Конкурентное бронирование одного слота не защищено блокировкой (SQLite, учебный проект):
  при одновременных запросах теоретически возможен перебор вместимости.
- Нет автоматической отметки «курьер опаздывает/не приехал» и переноса просроченных
  слотов.
