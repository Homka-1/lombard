## Что сделано
- **API-слой**: типы заявки, фото, оценок, оферты, выезда курьера, займа, платежей
  (`src/api/types.ts`); эндпоинты `applicationsApi`, `deliveryApi`, `loansApi`
  (`src/api/endpoints.ts`). `apiFetch` больше не перезаписывает заданный заголовок `Accept`.
- **Новые компоненты дизайн-системы** (`Form.tsx`): `Textarea` и `ChoiceGroup` — плитки выбора
  на нативных радиокнопках (`tile` — категории и дни, `slot` — интервалы курьера, «Занято» —
  недоступная плитка), как в артборде 05.
- **Мои заявки** `/client`: строки-«ведомость» с обложкой, номером, статусом, предоценкой;
  метка «Нужно ваше действие» (черновик, запрос фото, оферта, вызов курьера, выплата,
  просрочка); фильтр «В работе / Завершённые / Все»; пустое состояние с призывом оценить
  изделие.
- **Мастер заявки** `/client/new` по артборду 04: шаги «Изделие → Параметры → Фото →
  Проверка» (`Stepper`), проверка полей до отправки и разбор 422 от backend с кнопкой
  «Исправить», которая ведёт на нужный шаг.
  - Черновик создаётся на сервере при переходе к фото; адрес меняется на
    `/client/new?draft=ID` (перезагрузка страницы не теряет черновик), «Черновик сохранён в
    HH:MM».
  - `PhotoManager`: перетаскивание или выбор файлов, загрузка сразу на сервер, плитки
    загрузки, обложка («Главное», «Сделать главным» → `PUT …/photos/order`), удаление,
    отметка качества по `quality_score` и предупреждение «Фото N получилось нечётким или
    тёмным» с кнопкой «Переснять» (удаляет снимок и открывает выбор файла).
  - Боковые карточки «Ваша заявка» (параметры, «Изменить») и «Проверка фото» (количество,
    ракурсы, слабые снимки); советы «Как снять, чтобы оценка была точнее».
  - Повторная отправка после «Нужны фото»: заголовок «Дополнить заявку», комментарий
    эксперта, кнопка «Отправить повторно».
- **Карточка заявки** `/client/applications/:id` по артборду 05: заголовок со статусом и
  строкой «Заявка № … от …, золото 585, 4,2 г»; основная панель зависит от статуса:
  - черновик / запрос фото — продолжить заполнение, удалить черновик (с подтверждением);
  - ожидание эксперта и осмотра — что происходит и сколько ждать;
  - **оферта**: сумма займа крупно с клеймом пробы, «Вернуть до … — сумма», плашки «Оценка
    эксперта / Ставка / Срок», комментарий эксперта, срок действия; «Принять и вызвать
    курьера» (после принятия страница прокручивается к форме курьера) и «Отказаться» с
    необязательной причиной;
  - **вызов курьера** (`CourierForm`): город из `/delivery/cities`, адрес, дни и интервалы из
    `/delivery/slots` (занятые — недоступны, при 409 расписание перезапрашивается), телефон с
    маской (по умолчанию — из профиля), комментарий, «Изделие застраховано на …»; перенос
    визита, пока курьер не выехал;
  - **осмотр и выплата**: итог осмотра, предупреждение, если сумма снизилась, поле карты
    (маска, проверка Луна, подстановка тестовой карты) → `POST …/payout`;
  - **займ**: залоговый билет, «Погасить сегодня», срок, проценты, переход к займу, билет;
  - после погашения — **вызов курьера для возврата** (`POST …/return`), затем данные визита;
  - итоговые состояния: отказ эксперта (с причиной), отказ клиента, изделие возвращено,
    изделие перешло ломбарду.
  - Боковая колонка: предварительная оценка (диапазон, «Уверенность» — `role="meter"`,
    замечания к фото свёрнуты в `<details>`, миниатюры с просмотром в модальном окне),
    **«Ход заявки»** — пройденные статусы из истории с временем Казахстана (UTC+5), текущий
    шаг с подсказкой («Примите или откажитесь до …») и оставшиеся вехи обычного пути;
    контакт поддержки.
- **Займы** `/client/loans`, `/client/loans/:id`: действующие и закрытые, «Погасить сегодня»,
  «Вернуть до …, N дней осталось» / просрочка с льготным периодом; карточка займа — шкала
  срока, предупреждения «Срок скоро» и «Просрочка», погашение (разбивка тело + проценты),

## Как проверить
```bash
cd backend && alembic upgrade head && python -m app.seed && uvicorn app.main:app --reload
cd frontend && npm run dev          # http://localhost:5173 → «Войти» → карточка «Клиент»
cd frontend && npm test && npm run lint && npm run format:check && npm run design:check && npm run build
```
Сценарий в браузере: «Новая заявка» → Золото, название → проба 585, вес 4,2, состояние →
фото → «Отправить на оценку» → карточка с предоценкой. Шаги эксперта и курьера пока делаются
через Swagger (`/api/docs`, экраны — этап 11): `POST /api/expert/applications/{id}/take`,
`…/offer`, курьер `POST /api/courier/tasks/{id}/start|pick-up|deliver`, эксперт `…/inspection`.
Дальше в кабинете клиента: «Принять и вызвать курьера» → интервал → после осмотра карта
`4400 4301 2345 6789` → «Займы» → «Продлить» / «Погасить» → в карточке заявки «Вернуть
изделие».

## Принятые решения
- **Черновик создаётся при переходе к фото**, а не на первом шаге: фото привязаны к заявке на
  сервере, а пустых черновиков от «прокликивания» мастера не остаётся. Шаги 1–2 сохраняются
  одним `POST`/`PATCH`.
- **Мастер — один маршрут** `/client/new` с `?draft=ID` вместо отдельного «редактирования»:
  после создания черновика компонент не перемонтируется (иначе терялось состояние и
  выбранные файлы — найдено сквозной проверкой и исправлено).
- **Фото загружаются сразу при выборе**: клиент видит оценку качества до отправки, как в
  макете («Проверка фото»). Порог «слабого» снимка — `quality_score < 50` (`LOW_QUALITY`).
- **Таймлайн = история + вехи**: прошлое берётся из `history` как есть (с повторными кругами
  после «Нужны фото»), будущее — из фиксированного списка вех; из комментариев показываются
  только запрос фото и причина отказа, служебные расчёты скрыты.
- **Подсказка тестовой карты всегда под полем** (не вместо ошибки): после отказа банка
  пользователь сразу может подставить рабочую карту.
- Пункт меню «Документы» из макета не добавлен: отдельного раздела документов нет, залоговый
  билет доступен из займа и карточки заявки.
- Блок макета «Есть вопрос по оценке? Открыть чат» заменён на телефон поддержки — чата в
  backend нет.

## Известные проблемы и техдолг
- Экраны эксперта, курьера и админа — заглушки (этап 11); до этого их шаги делаются через
  Swagger.
- Статус заявки не обновляется сам (нет поллинга/WebSocket) — обновляется при заходе на
  страницу и после действий; колокольчик показывает только счётчик, списка уведомлений нет.
- Слабость снимка определяется только по `quality_score` при загрузке; подробные причины
  («пересвечено», «похоже на фото 1») backend считает при отправке — они показаны в
  карточке в «Замечаниях к фото».
- Перетаскиванием нельзя менять порядок фото — только «Сделать главным».
- Варианты срока продления (7/14/30/60) зашиты в UI; недопустимый для категории срок
  backend отклоняет, и ошибка показывается в окне продления.
- Нет страницы профиля и смены пароля (API есть).
