## Что сделано
- **Домен** `app/domain/loan_calc.py` (чистые функции для переноса в демо):
  `interest_for()` (простые проценты, округление до тиына «половина вверх»),
  `max_loan_amount()` (стоимость × LTV, вниз до 100 ₸), `quote()` → `LoanQuote` (проценты,
  к возврату, дата возврата, конец льготного периода +30 дн., номинальная годовая ставка,
  «график» — сумма к возврату на 1, 7, 14, … день и в дату возврата), `validate_terms()`
  (LTV ≤ категории, ставка 0,01 % … ставка категории, срок в пределах категории, сумма
  ≥ 1 000 ₸, ≤ лимита, кратна 100 ₸), `format_rate()` («0,25 % в день»).
- **Сервис** `app/services/review.py`: очередь (`new` / `mine` / `all`, FIFO по времени
  отправки), «взять в работу» (идемпотентно для того же эксперта, 409 для другого),
  предпросмотр условий, отправка предложения (экспертная оценка + оферта с `expires_at`,
  отклонение от авто-оценки в `details`, прежняя оферта → `SUPERSEDED`), запрос
  дополнений и отказ (с обязательным комментарием), принятие/отказ клиента, ленивое
  истечение оферты (`expire_offer_if_needed`) и пакетное `expire_offers(now)` для будущего
  джоба/симуляции времени.
- **Уведомления** `app/services/notifications.py` — `notify()` пишет in-app `Notification`
  (клиенту: предложение, нужны дополнения, отказ, истечение; эксперту: принято/отклонено).
- **Публичный калькулятор** `app/services/calculator.py` + `POST /api/calculator`:
  категория по `id` или `code`; либо `market_value`, либо параметры изделия (металл, проба,
  вес, бренд, состояние) → оценка формулой этапа 5 без фото; опционально желаемая сумма.
- **API**: `/api/expert/queue`, `/api/expert/applications/{id}/{take|quote|offer|need-info|reject}`,
  `/api/applications/{id}/offer/{accept|decline}`. В карточке заявки новые поля: `client`,
  `expert`, `expert_appraisal`, `offer` (с расчётом `quote` и графиком), `actions`
  (доступные текущему пользователю действия — для кнопок UI).
- **Настройка** `LOMBARD_OFFER_TTL_HOURS` (72 ч) — `.env.example`, README.
- **Тесты**: `test_loan_calc.py` (19: проценты и округление, совпадение с цифрами макета —
  119 000 ₸ × 80 % = 95 200 ₸, проценты 5 712 ₸, вернуть 100 912 ₸; график; валидация),
  `test_review.py` (28: полный сценарий «заявка → предоценка → очередь → взять → калькулятор

## Принятые решения
- **Займ — один платёж** (как в ломбардах): проценты простые за фактические дни (минимум 1);
  «график» — справочная таблица суммы к возврату по дням, а не аннуитет.
- **Сумма займа округляется вниз** до 100 ₸, чтобы никогда не превышать LTV (в предоценке
  этапа 5 ориентир округлялся до ближайших 100 ₸ — это лишь ориентир).
- **Эксперт не может ухудшить условия категории**: LTV ≤ LTV категории, ставка ≤ ставки
  категории (то, что обещано на лэндинге, — верхняя граница). Можно предложить меньше.
- **Действовать может только взявший заявку эксперт**; админ видит очередь, но не ставит
  оценки (машина состояний разрешает эти переходы только роли EXPERT). Для этого роутер
  эксперта использует `require_role(Role.EXPERT)`, а очередь — `ExpertUser` (эксперт+админ).
- После `NEED_INFO` и повторной отправки заявка снова в общей очереди `new`, но в элементе
  очереди виден эксперт, который вёл её раньше; взять её может любой эксперт.
- **Истечение оферты ленивое**: проверяется при принятии/отказе (истечение коммитится,
  затем 409), плюс функция `expire_offers(now)` для джоба. Истёкшая оферта → заявка
  `OFFER_DECLINED` (системой); отдельного статуса «истекла» в машине состояний нет.
- **Даты займа — по времени Казахстана** (UTC+5, фиксированное смещение без tzdata —
  работает и на Windows); метки времени по-прежнему в UTC.
- `offer.quote` в карточке считается «при выдаче сегодня»: окончательные даты фиксируются при
  выдаче средств (этап 8).
- Калькулятор по параметрам считает без фото, поэтому уверенность ниже и диапазон шире,
  чем у предоценки заявки.

## Известные проблемы и техдолг
- Нет перехода «вернуть заявку в очередь» (`UNDER_REVIEW → PRE_ESTIMATED`), если эксперт
  взял заявку и пропал; нет переназначения админом. Можно добавить в машину состояний на
  этапе 8 (админ-эндпоинты).
- Эксперт не может отозвать/изменить отправленную оферту (в сервисе замена поддержана —
  `SUPERSEDED`, — но перехода `OFFER_SENT → UNDER_REVIEW` нет).
- Нет эндпоинта списка уведомлений — записи создаются, чтение/«прочитано» — этап 8.
- Истечение оферт не запускается по расписанию (нужен джоб или вызов при «перемотке
  времени» — этап 8).
- `GRACE_DAYS` в `loan_calc.py` дублирует настройку `grace_period_days` (обе = 30); на этапе 8
  передавать значение из настроек.
