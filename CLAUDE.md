# CLAUDE.md — «Ломбард онлайн»

Учебный проект №107: **онлайн-ломбард — оценка залога по фото и выдача средств
(оценка эксперта, вызов курьера за изделием).**

Этот файл — главный источник правды для агента. Читай его целиком в начале каждой сессии.

---

## 1. Правила работы агента (ОБЯЗАТЕЛЬНО)

1. **Поэтапная разработка.** Проект делается строго по этапам из раздела 4.
   За один раз выполняется **ровно один** этап.
2. **Старт этапа — только по команде пользователя «Следующий этап».**
   Без этой команды новый этап не начинается (можно отвечать на вопросы и
   исправлять ошибки текущего/прошлого этапа).
3. **Перед началом этапа:**
   - прочитать `docs/STATUS.md` (сводка) и заметки прошлого этапа
     `docs/stage-NN.md` — раздел «Заметки для следующего этапа»;
   - учесть известные проблемы и долги из этих заметок;
   - в `docs/STATUS.md` пометить новый этап как `🟡 в работе`.
4. **В конце этапа:**
   - создать `docs/stage-NN.md` по шаблону `docs/_template.md`
     (что сделано, как проверить, решения, проблемы, заметки для следующего этапа);
   - обновить таблицу в `docs/STATUS.md` (`✅ завершён`, дата, коммит);
   - прогнать проверки этапа (тесты/линтер/сборка) и честно записать результат;
   - закоммитить и запушить в рабочую ветку.
5. **Фронтенд** делается с использованием плагина/скилла **frontend-design**
   (если доступен в сессии — вызвать его перед написанием UI; если нет —
   следовать его принципам: продуманная типографика, характерная палитра,
   не «шаблонный» вид, адаптивность, доступность).
6. Язык интерфейса и документации — **русский**. Код, идентификаторы, коммиты —
   на английском (коммиты можно на русском, но единообразно).
7. Не добавлять внешние платные сервисы. Всё должно запускаться локально
   одной-двумя командами. Внешние интеграции (платежи, SMS, ИИ-оценка) —
   **моки** с понятным интерфейсом для замены.

## 2. Описание продукта

### Роли
| Роль | Что делает |
|------|------------|
| **Клиент** | Регистрируется, создаёт заявку на оценку: категория, описание, параметры (металл, проба, вес, бренд, состояние), загружает 1–6 фото. Получает предварительную и экспертную оценку, принимает оферту, вызывает курьера, получает деньги, гасит/продлевает займ. |
| **Эксперт (оценщик)** | Видит очередь заявок, смотрит фото, ставит экспертную оценку и условия займа (или отклоняет / запрашивает доп. фото). После доставки подтверждает подлинность изделия при осмотре. |
| **Курьер** | Видит назначенные выезды, меняет статусы: «выехал» → «забрал изделие» → «доставил в ломбард». Также возвращает изделие после погашения. |
| **Администратор** | Справочники (категории, цены металлов, ставки), пользователи и роли, назначение курьеров, статистика. |

### Основной сценарий (жизненный цикл заявки)
```
DRAFT → SUBMITTED → PRE_ESTIMATED (авто-оценка по фото и параметрам)
      → UNDER_REVIEW (эксперт взял в работу)
      → OFFER_SENT (экспертная оценка + условия займа)   | REJECTED | NEED_INFO
      → OFFER_ACCEPTED (клиент принял)                   | OFFER_DECLINED
      → COURIER_SCHEDULED → COURIER_EN_ROUTE → ITEM_PICKED_UP → ITEM_DELIVERED
      → INSPECTED (эксперт подтвердил на осмотре; сумма может быть скорректирована)
      → FUNDS_ISSUED (выдача средств на карту/счёт — мок, формируется залоговый билет)
      → LOAN_ACTIVE → REPAID → ITEM_RETURNED (курьер возвращает)
                    → EXTENDED (продление) → LOAN_ACTIVE
                    → OVERDUE → FORFEITED (изделие переходит ломбарду)
```

### Бизнес-правила (учебные)
- **Предоценка**: `рыночная_стоимость = f(категория, металл, проба, вес, бренд, состояние)`
  + «анализ фото» (мок-сервис: проверка количества/качества фото, эвристика —
  размер, резкость/яркость; интерфейс `PhotoAppraiser` для замены на ML).
  Выдаётся диапазон `min–max` и уровень уверенности.
- **Займ**: сумма = рыночная стоимость × LTV категории (напр. золото 80%,
  электроника 50%, часы 60%). Ставка — % в день из справочника. Срок 7–60 дней.
- **Продление**: оплата начисленных процентов, срок сдвигается.
- **Просрочка**: льготный период 30 дней, затем `FORFEITED`.
- **Регион — Казахстан.** Валюта — тенге (KZT, знак `₸`); все суммы хранятся в тиынах
  (integer, 1 ₸ = 100 тиын), даты — UTC. Формат суммы: `16 100 ₸` (неразрывный пробел
  между разрядами и перед знаком).
- Телефоны — казахстанские: `+7 7XX XXX-XX-XX` (мобильные коды 700–708, 747, 771, 775–778),
  городские — например, Алматы `+7 727 …`. Адреса в демо-данных — города Казахстана.

## 3. Технологический стек и структура

| Слой | Технологии |
|------|-----------|
| Backend | Python 3.12+, **FastAPI**, SQLAlchemy 2.0, Alembic, Pydantic v2, SQLite (dev) / PostgreSQL (опц.), JWT (python-jose / PyJWT), passlib/bcrypt, Pillow (анализ фото) |
| Frontend | **React 18 + TypeScript + Vite**, React Router, TanStack Query, CSS-модули/CSS-переменные (дизайн по frontend-design), без тяжёлых UI-китов |
| Тесты | pytest + httpx (backend), Vitest + Testing Library (frontend), Playwright (e2e-смоук) |
| Дизайн | Adobe Illustrator (ExtendScript `.jsx`) + SVG/PNG-превью, сгенерированные Node-скриптом и Playwright |
| Инфраструктура | `docker-compose.yml` (опционально), `Makefile`/npm-скрипты, seed-данные |

```
lombard/
├── CLAUDE.md               # этот файл (план и правила)
├── README.md               # запуск, демо-аккаунты

├── docs/
│   ├── STATUS.md           # сводная таблица статусов этапов

    ├── src/
    │   ├── api/            # клиент API
```

### Команды (заполняются по мере появления)
```bash

cd backend && pip install -e ".[dev]" && uvicorn app.main:app --reload   # http://localhost:8000/docs
cd backend && pytest
# frontend
cd frontend && npm install && npm run dev                                 # http://localhost:5173
cd frontend && npm test && npm run build
```

## 4. Поэтапный план разработки

> Статусы этапов ведутся в `docs/STATUS.md`. Подробные отчёты — `docs/stage-NN.md`.

### Этап 0 — Планирование
- CLAUDE.md с планом, структура `docs/`, шаблон отчёта, `STATUS.md`.
- **Готово, когда:** план согласован, документы в репозитории.

### Этап 1 — Макет дизайна в графическом редакторе (Adobe Illustrator, скриптом)
- Вызвать скилл **frontend-design**: визуальная концепция («надёжность + ювелирная
  точность»), палитра, шрифтовая пара, сетка, тон иллюстраций/иконок.
- `design/tokens.json` — единый источник дизайн-токенов (цвета, шрифты, размеры,
  отступы, радиусы, тени). Его же позже использует фронтенд (этап 9).
- `design/illustrator/lombard-mockup.jsx` — **ExtendScript для Adobe Illustrator**
  (File → Scripts → Other Script…): создаёт документ с монтажными областями,
  слоями, именованными цветовыми образцами (swatches) и текстовыми стилями,
  читает `tokens.json`. Монтажные области:
  1. Дизайн-система (палитра, типографика, кнопки, поля, бейджи статусов, степпер)
  2. Лэндинг (desktop 1440) — герой, «как это работает», калькулятор, FAQ
  3. Лэндинг (mobile 375)
  4. Клиент: мастер заявки (шаг загрузки фото)
  5. Клиент: карточка заявки — таймлайн, предоценка, оферта, вызов курьера
  6. Эксперт: экран оценки (галерея фото + форма + калькулятор)
  7. Курьер: список выездов (mobile 375)
  8. Админ: дашборд
- Так как Illustrator в контейнере недоступен — генератор-«двойник»
  `design/scripts/build-svg.mjs` строит те же экраны в SVG из того же описания
  макета (`design/layout/*.json` или общий JS-модуль), и рендер в PNG через
  Playwright → `design/previews/*.png` для просмотра без Illustrator.
- `design/README.md` — как запустить скрипт в Illustrator, как пересобрать превью,
  описание концепции и обоснование решений.
- **Готово, когда:** скрипт Illustrator синтаксически корректен (ES3/ExtendScript,
  без современных конструкций), SVG/PNG-превью всех 8 артбордов сгенерированы и
  закоммичены, токены зафиксированы.

### Этап 2 — Каркас проекта
- Структура `backend/` и `frontend/`, `.gitignore`, `README.md`, `.env.example`.
- FastAPI-приложение с `/api/health`, конфиг через pydantic-settings, CORS.
- Vite + React + TS заготовка, прокси на backend, страница-заглушка.
- Линтеры/форматтеры (ruff, eslint/prettier), первый тест pytest и vitest.
- **Готово, когда:** оба приложения запускаются, `/api/health` отвечает, тесты зелёные.

### Этап 3 — Модель данных и БД
- Модели: `User`(роль), `Category`, `MetalPrice`, `Application`, `Photo`,
  `Appraisal` (auto/expert), `Offer`, `CourierTask`, `Loan`, `Payment`,
  `StatusHistory`, `Notification`.
- Alembic-миграции, seed-скрипт (категории, цены металлов, демо-пользователи всех ролей).
- Сервис-машина состояний заявки (разрешённые переходы + кто может их делать) с юнит-тестами.
- **Готово, когда:** `alembic upgrade head` + seed работают, тесты машины состояний зелёные.

### Этап 4 — Аутентификация и роли
- Регистрация/вход (JWT access + refresh), `/api/auth/me`.
- Зависимости `require_role(...)`, хеширование паролей.
- **Готово, когда:** тесты на регистрацию, вход, доступ по ролям проходят.

### Этап 5 — Заявки, загрузка фото, автоматическая предоценка
- CRUD заявки клиента, загрузка 1–6 фото (валидация типа/размера, превью), раздача файлов.
- `PhotoAppraiser` (мок-анализ фото через Pillow) + `PriceEstimator` (формула по справочникам).
- Отправка заявки → статус `PRE_ESTIMATED` с диапазоном и уверенностью.
- **Готово, когда:** через Swagger можно создать заявку с фото и получить предоценку; тесты.

### Этап 6 — Экспертная оценка и оферта
- Очередь эксперта, взятие в работу, экспертная оценка, запрос доп. информации, отказ.
- Калькулятор займа (LTV, ставка, срок, сумма к возврату, график) — отдельный сервис + тесты.
- Клиент принимает/отклоняет оферту; публичный калькулятор `/api/calculator`.
- **Готово, когда:** сценарий «заявка → оферта → принятие» проходит в интеграционном тесте.

### Этап 7 — Вызов курьера и логистика
- Слоты времени, адрес, контактный телефон; создание `CourierTask`.
- Назначение курьера (админ или авто — наименее загруженный).
- Статусы курьера, осмотр экспертом при доставке (`INSPECTED`, возможная корректировка суммы).
- **Готово, когда:** интеграционный тест «принятие оферты → курьер → осмотр» зелёный.

### Этап 8 — Выдача средств, займ, погашение
- Мок-платёжный шлюз (`PaymentGateway`): выдача на карту, приём оплаты.
- Залоговый билет (номер, условия; HTML/PDF для скачивания).
- Погашение, продление, расчёт просрочки (джоб/эндпоинт для симуляции времени), возврат изделия курьером, `FORFEITED`.
- Уведомления в личном кабинете (и лог «SMS/email»-моков).
- Админ-эндпоинты: справочники, пользователи, статистика.
- **Готово, когда:** полный backend-сценарий от заявки до возврата изделия покрыт тестом.

### Этап 9 — Frontend: дизайн-система и публичная часть (frontend-design)
- Вызвать скилл **frontend-design**; **реализовывать по макету этапа 1**
  (`design/previews/*.png`), токены брать из `design/tokens.json`
  (генерация CSS-переменных из токенов).
- Базовые компоненты: Button, Input, Select, Card, Badge статуса, Stepper, Modal, Toast, Uploader.
- Лэндинг (как это работает, калькулятор займа, FAQ), вход/регистрация, layout с навигацией по ролям.
- **Готово, когда:** лэндинг и авторизация работают с реальным API, адаптив до 360px,
  визуально соответствуют макету.

### Этап 10 — Frontend: кабинет клиента
- По макетам артбордов 4–5.
- Мастер создания заявки (шаги: категория → параметры → фото drag&drop → проверка).
- Список заявок, карточка заявки с таймлайном статусов, предоценка, оферта (принять/отклонить).
- Вызов курьера (выбор слота, адрес), займ: график, погашение, продление, залоговый билет.
- **Готово, когда:** клиент проходит весь свой путь в браузере.

### Этап 11 — Frontend: кабинеты эксперта, курьера, администратора
- По макетам артбордов 6–8.
- Эксперт: очередь, просмотр фото (галерея/зум), форма оценки с живым калькулятором, осмотр.
- Курьер: список выездов на сегодня, смена статусов, мобильная вёрстка.
- Админ: справочники, цены металлов, пользователи, назначение курьеров, дашборд-статистика.
- **Готово, когда:** все роли проходят свои сценарии в браузере.

### Этап 12 — Тестирование, полировка и сдача
- E2E-смоук (Playwright) полного сценария на всех ролях.
- Обработка ошибок, пустые состояния, загрузки, доступность (a11y), финальный UI-проход,
  сверка со скриншотами макета.
- `docker-compose`, README с инструкцией и демо-аккаунтами, скриншоты, итоговый отчёт.
- **Готово, когда:** проект поднимается «с нуля» по README, все тесты зелёные.

- Создан `docs/stage-NN.md`, обновлён `docs/STATUS.md`.
- Изменения закоммичены и запушены в рабочую ветку.
